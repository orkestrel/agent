# Refuse-by-default semantics

This record rules on the `reason` family's states, validation, contracts, and release dependencies as of 2026-11-04.

Paths are under the named package's `src/core/` unless they name `tests`; `contract` cites its `src/core/`. [ran] marks readings on published 0.0.21 builds under `agent/node_modules` with Node 22.23.4 on 2026-11-04: amendments, parser and default probes, and guard checks; everything else is read.

**1. States and the partition.** A check, rule, finding, determination, and premise carries `state: 'met' | 'unmet' | 'unread'`; no boolean `met`, `applied`, or `conclusion` survives (`reason types.ts:137,544,558`; `qualifier types.ts:69,79`; `program types.ts:89`). `LogicalResult.conclusion` is a state, and `brief BriefCompiler.ts:161` refuses on `state !== 'met'`. `RuleResult` gains `checks: readonly CheckResult[]`, atoms in extraction order with their final states, and `qualifier` builds premises from it instead of re-reading the pre-pass snapshot (`Qualifier.ts:245,264`). An unread input is never a value. Closed-world covers exactly a key an enabled rule of the same definition concludes (`extractConclusions`, `helpers.ts:1014`, computed once per definition); every other absence is unread, the `qualification.*`, `outcome.*`, and `aggregate.*` projections included. A settled pass projects its fired conclusion values and an explicit `false` for each conclusion key of a settled unfired rule (`qualifier helpers.ts:327-330`); an unread pass projects nothing; `validate` refuses a conclusion value of `false`. The engine refuses a subject that supplies a conclusion key (`{age:15, adult:true}` fires `ok` on 2026-11-04 [ran]).

**2. Logic.** Strong Kleene at the connectives (`LogicalReasoner.ts:588-601`). Forward (`:209-242`), phase A: an atom on a conclusion key absent from the overlay reads unread and its rule holds; iterate to convergence. Phase B: each absent conclusion key whose concluding rules have all settled closes (`equals` and `any` unmet, `not` and `none` met, ordering and range unread); held rules re-evaluate; a firing derives and returns to phase A. A derivation onto a key already closed and read by a fired rule is the error `unstratified`; a depth-cap hit is an error; after the last phase any unread rule refuses. This closes the retraction case (`not(a)` at priority 0 gives `nb:false, nc:true` on 2026-11-04 [ran]). Backward: `#establish` (`:368-381`) returns the state; a candidate matches by field only, not value (`:407`), and the goal atom is re-evaluated after it fires (`score above 5` proves through `score equals 5` on 2026-11-04 [ran]); an unread candidate makes the goal unread. Backward closing keys through forward's settle loop is not wrong, provided a test holds `rules` and `conclusion` equal to forward's on every definition; both compute the same supported model, and only the trace differs. The overlay-mismatch error is dropped: the engine resolves a conclusion key by `formatField` on both the write and the read, so a definition the engine reads correctly is never refused for it.

**3. The channel.** `success === (errors.length === 0)` stays (`LogicalReasoner.ts:171`, `QuantitativeReasoner.ts:190`, `InferentialReasoner.ts:207`); `program helpers.ts:342-345,933` read `errors.length` and never `.success` [ran, an emulated `success:false` with empty `errors` approved]. `success` is the only verdict. `faults: readonly AuditFault[]` (`contract types.ts:1056-1088`; `ExtraFault` sits outside `Fault`) carries every refusal a question can be derived from: an engine unread is `{ reason: 'missing', path, expected }` with `expected` mapped from the operator, a wrong type is `{ reason: 'type', path, expected, received }`; input leaves only, transitively, a conclusion key never. `errors` contains one string per fault plus the errors no fault can say: the supplied conclusion key, an unknown operator, the depth cap, `unstratified`. `qualifier`: an unread pass pushes an unscoped synthetic referral through `deriveFindingEligibility`'s `failed` (`helpers.ts:494`), projects nothing, and continues so a later restriction outranks it (`Qualifier.test.ts:311`); the break at `Qualifier.ts:281` fires only on errors that are not faults; `QualificationResult.success` is false and it carries `faults` with a `qualification.<pass>.*` path replaced by that pass's leaves. `program`: status `incomplete`, eligibility `referral` (`helpers.ts:151`), `decision` undefined (`:347-348`); `ProgramResult` and `AggregateResult` carry `faults`, `repairs`, and `defaulted`. `rater helpers.ts:397` `sumAmounts` is `undefined` when any worksheet is not `success`.

**4. `Factor.required` stays, narrowed** to "must apply: an unmet check is an error" (`tests/src/core/reasoners/QuantitativeReasoner.test.ts:429`; without it `{value:100, success:true}` [ran]); an unread source is unread for every factor (`QuantitativeReasoner.ts:276-284`); `strict` drops silently (`:221-228`) and is no replacement.

**5. The shape and the door.** The stored form is `shape?: ContractShape`, whole; the schema is `compileSchema(shape)`, which emits `additionalProperties: false` explicitly [ran], so the round trip widens only on `pattern` and `format` (`SchemaShaper.ts:152-155`). A `pattern` refuses after JSON ("string pattern must be a RegExp" [ran]), so the deep `validate` refuses `pattern` in a definition's shape at authoring; a `raw` or `json` field read by a rule is a warning, the engine's typed read its backstop (the raw guard accepts every defined value, `ContractCompiler.ts:972-973`; `'700'` passes a raw field unchanged [ran]). Roots only: the program subject per subject before `aggregateSums` (`Program.ts:394`); the authority on `{ outcome }` and a gate on the batch record with their own shapes; the recipe on the generated subject after clarify and computations; optional `shape` on `Definition`, `QualificationDefinition`, `RatingDefinition`; pass-level definitions carry none, because the merged subject holds `qualification` (`Qualifier.ts:277`, faults `extra` [ran]). The door, `createContract(shape)` memoized by identity: (1) an `explain` fault refuses; (2) `extra` from `audit` refuses, and an open object is the only escape (`:927`); (3) an audit at `FAULT_LIMIT` (64, `constants.ts:358`; `limitEntries` at `:1611`) refuses, because a 64th fault hides the typo [ran]; (4) a `variant` or `oneOf` fault refuses, because a union repairs by declaration order and an object union parses `{amount:'500'}` to `{}` [ran]; (5) `parse` gives the subject; (6) the remaining `type` faults are repairs, accepted only when lossless: a number from a string whose `trim()` equals `String(parsed)` (`'30'`, `' 30 '` pass; `'30.0'`, `'1.500'`, `'007'`, `'0x10'`, `'1e3'`, `'+5'`, `'.5'`, `'-0'`, `'9007199254740993'`, `'1e-400'` refuse [ran]), a boolean from `'true'` or `'false'` only (`'1'`, `'0'`, `1`, `0` refuse), a literal from its trimmed text, a string from a finite number; any other repair refuses. Accepted repairs are `repairs: readonly AuditFault[]` on the result. A required key absent refuses at the door even where the engine would settle `age 15 and credit above 600`; the author who wants that lever declares the field optional with no default. `null` is a value: with a shape it is a `type` fault unless the field's shape admits `null` (a nullable, or the `union[inner, null]` a round trip produces [ran]); the engine settles `equals null` and `not null` on a present field, ordering on `null` is unread, and the door never fills a `null`. `validate` refuses an aggregate field or partition whose shape admits `null` or absence without a default (`sumFields` skips, `formatGroupKey` pools into `''`, `program helpers.ts:620,653`). The model's route under either answer on `Tool`'s extras: `createTool({ parameters: schemaToParameters(contract.schema), strict: false, execute })` with this door first inside `execute`, because `Tool` with a `contract` runs `explain` only and hands `parse`d arguments on (`tool Tool.ts:64,80-82`), erasing extras and repairs [ran], and `schemaToParameters` returns the schema record as is (`contract helpers.ts:1970-1977`), so `default` reaches MCP and the LLM with `tool` and `mcp` staying on 0.0.21 this wave. `defaulted` means filled at this door; a client that honours the advertised default sends a stated value. A foreign JSON Schema declared by a `reason` definition, recipe, authority, or gate enters through `schemaToShape(schema, { strict: true })` of section 14, never the lenient conversion. Advertised tool `parameters`, MCP descriptor `inputSchema` and `outputSchema`, and an agent run's `schema` use the lenient conversion; see `failopen.md`, ruling 5.

**6. Optional and defaults.** An optional field may carry a default in the shape (section 14). The door fills it through `parse`; `defaulted` lists the paths own-absent or own-`undefined` in the input and own-present in the parsed output, computed by that diff over object and array nesting, not from a shape walk, so it matches what `parse` did. Without a default the field is unread only when a rule reaches it. `validate` refuses a default on a required key (a `required` key with `default` stays required and the keyword is an annotation) and a shape that declares a conclusion key. A computed entity's confidence is the minimum of its inputs' and its own constant (`Clarifier.ts:160-191`; a default `rate` yields `premium` at 0.9 on 2026-11-04 [ran]).

**7. Typed reads, always on, shape or not,** because a `raw` field and an open object's extras are never normalized. Gate first: absent, object, array, `NaN`, `Infinity`, bigint actuals are unread. Ordering and range need finite numbers on both sides. `equals` and `not`: same primitive type settles by `===`; types differ reads unread; a string actual that is blank or differs from its trim reads unread. The coercion rule is dropped because it settles `'no'`, `'off'`, `'False'`, `' true '`, and `''` against `equals false` as unmet [ran], a silent pass of the values it exists to catch, and because it is one-directional (`parseString(true)` is `undefined`, `parsers.ts:60-65`, so `true not 'true'` settled met). So `x not 'none'` over 90 is unread and the author writes `x not null`. `any` and `none`, per element: an exact `===` hit settles (`any` met, `none` unmet); otherwise any element of another type makes the read unread; otherwise settled. Lookup keys: string, finite number, boolean; `fallback` only for an unknown key or no band (`helpers.ts:217,231`), traced; `parseNumberField` (`:209,220`) goes.

**8. Deep `validate`, on by default, memoized by a `WeakMap` on the definition.** `validate: true` alone refuses only an empty `rules` [ran]; the exact guards (`validators.ts:649-769`) add the unknown operator, transform, aggregation, and `rules:[null]`, on which `validate` throws a bare `TypeError` on 2026-11-04 [ran]. Order: exact guard, then connective arity (`not` one, `implies` and `xor` two, `and` and `or` at least one; `and []` fires and `not(a,b)` drops `b` [ran]); range values two finite numbers in order; `any` and `none` a non-empty primitive array; conclusions only `equals` atoms under `and`, never `false`; duplicate ids, empty `rules`, `groups`, `factors`, and a confidence out of range as errors; static stratification over the conclusion-key graph with negative edges, refusing a non-stratified definition before it runs; `Check.value` an `isJSONValue` (`notOf(unionOf())` at `validators.ts:369` is always true). With a shape: every read path is in the shape, a conclusion key, or an engine key; every expected value satisfies `createContract(fieldShape).is(expected)`, per element for a list (`age equals '18'` on a number field is unmet forever on 2026-11-04 [ran]; `isLiteralValue` excludes `null`, so the check goes through the field's shape, not that guard); a string expected needs a field whose shape admits it as a literal, because `stringShape` admits `' FL '` and `''` with no repair [ran] and free text is never compared by equality. `DEFAULT_VALIDATE` (`constants.ts:21`) becomes `true`; `qualifier.validate` calls the engine's per pass (`isQualificationPass` is the exact guard only, `validators.ts:187-189`); `qualifier`'s `metadata: isRecord` (`validators.ts:234`) becomes `recordOf(isJSONValue)`.

**9. Zero applied groups.** Every non-application settled gives `base` plus the identity with `success` true (`{flood:false}` [ran]); empty `groups` or `factors` is invalid (`rater tests/src/core/Rater.test.ts:555` changes); `minimum` and `maximum` over nothing stay the `NaN` error.

**10. Contracts in every package, first release.** `shapers.ts` and `contracts.ts` in `reason`, `qualifier`, `rater`, `program`, `interpret`: the subject per bundle, each definition, each result, the interpretation, the program result, the response. Definitions cross on `is` only, because `parse` turns `enabled:'0'` into `false` and accepts padded operators [ran]; the lockstep test holds `is ⟹ guard` (depth 5 on a depth-4 shape is guard true and `is` false [ran]). `Expression` is one operands array at depth 8 (5,622 bytes, 17 ms [ran]) with arity left to `validate`, since arity in the shape refuses at depth 7 [ran]; `SymbolicExpression` at depth 6, binary. Results cross as a JSON projection shaped at the boundary, non-finite as `null` and `undefined` omitted, because the engine publishes `NaN` by design; in-memory results and guards stay.

**11. `interpret` and `brief`.** `Recipe.shape` replaces `EntityMapping.required`, `Recipe.defaults`, and `FieldDefault` (`interpret types.ts:82,86-89,135`); `#fillDefaults` (`Clarifier.ts:138-151`) is the door's `parse`; `#collectAmbiguities` (`:236-251`) reads `missing` faults; `Ambiguity` and `Gap` carry the `AuditFault` with question text from the shape's `description`. `subject` is omitted while a required ambiguity is open (`Interpret.ts:311`); a mapping collects many only when its field's shape is an array; `brief helpers.ts:1333` maps provenance to the given category.

**14. `contract` 0.0.22.** Types: `OptionalShape.default?: JSONValue`; `OptionalShapeOptions { default?: JSONValue }`; `optionalShape(inner, options?)`; `JSONSchema.default?: JSONValue`; `SchemaToShapeOptions { strict?: boolean }` on `schemaToShape(schema, options?)`. Builder (`shapers.ts:603-609`): `default` must pass `isJSONValue`, is cloned through `cloneJSONValue`, and is frozen; a present `default: undefined` is a `structure` refusal. `ShapePass`: optional members become `['inner', 'default']` (`:288-290`), the child walk unchanged (`:1102-1108`); two `placement` refusals beside `:520-528`: a defaulted optional under a `union` ancestor, because a guard-valid value returns by identity (`ContractCompiler.ts:1279`) and `{n:5}` would never fill while `{n:'5'}` filled unreported, and a defaulted optional as a property of an open object, because `{licenced:false}` then fills `licensed:true` with empty `audit` and `explain` [ran]; the raw vocabulary (`:640-655`) admits `default` as a JSON value (`rawShape` refuses the keyword on 2026-11-04 [ran]). `ShapeCloner.#captureWrapper` (`:571-583`) captures `default` through `cloneJSONValue`; on 2026-11-04 `cloneShape` drops it and `createContract` owns through the cloner, so without this every default vanishes silently [ran]. `ContractCompiler`: at compile, each default is checked against the full compiled guard of its `inner`, refinements included, refusing with code `structure` at `[...path, 'default']`, because a restored `{ default: -5 }` under `min: 0` never met a builder and `validateShape` passes it on 2026-11-04 [ran]; the object parser fills at both absence sites, own-absent (`:1188`) and own-`undefined` (`:1193`), through `entry.parse(default)`, a fresh tree per parse with nested defaults applied, presence tested by own key so `default: null` works; the property schema (`:697-699`) carries `default`; `is` (`:968`), `audit` (`:1614`), `explain` (`:1938`), `generate` (`:2195`) unchanged. Laws: `audit` empty iff `is`, `explain` empty iff `parse` defined, `parse` defined implies `is(parse)` all hold, since an absent optional stays canonical and the compile check keeps the fill inside `inner`. `SchemaShaper` lenient: `default` carried for a key not in `required` whose inner is a primitive or literal a leaf guard accepts (it imports validators and parsers, not the compiler, `:20-21`), dropped otherwise. `schemaToShape` strict: refuses, with code `structure`, a malformed keyword, `pattern`, `format`, a contradictory or malformed bound, a `required` name not in `properties`, breadth past `INFER_BREADTH_LIMIT`, and any node the lenient walk would widen to `raw`, including a root type typo; an absent `additionalProperties` closes the object. Not in 0.0.22: `stringShape` trimming (free text is not a category), `isNumber(NaN)` (`typeof`, and `isFiniteNumber` exists), a safe-integer `integerShape` (`JSON.parse` has already rounded the literal, and the door's lossless rule refuses the string), the lenient conversion's behaviour, and `Tool`'s extras, which is ruled in `failopen.md`. Failing tests first: `parse({})` fills `{a:3}` and `parse({a:undefined})` the same; `is({})`, `audit({})`, `explain({})` clean; two parses of an object default are distinct objects; `schema.properties.a.default === 3`; `cloneShape` keeps a frozen copy, not the caller's reference; a JSON round trip of a defaulted shape compiles equal; `default: -5` under `min: 0` refuses at `createContract`; a default under `unionShape` and under an open object refuse `placement`; `rawShape` accepts `default: 3` and refuses `default: undefined`; lenient `schemaToShape` carries a valid default and drops `'x'` on a number; strict refuses each listed keyword and closes an absent `additionalProperties`.
