# Measurement design

This file is the home of every unit's gate, every instrument, and every GPU step's cap and order. `designs/runs.md` owns how a GPU step runs; `tenets.md` § Evaluation owns the evaluation canon; `research/evidence.md` owns the readings.

## Cheap-first order

Every unit runs its acceptance in this order and stops at the first failure:

1. Format, lint, and typecheck on the changed scope.
2. The touched test file.
3. The project tests.
4. One mutation probe on the load-bearing line: disable it, watch the test fail, restore it.

Every medium unit then gets one independent review, per the size gate of `@orkestrel/scaffold` `.agents/orchestration.md` § Size gate.

## Method

Every gated bench reading from rc-a3b on follows this method; a brief that departs from it states the departure and its reason before the run. The user delegated the measurements on 2026-11-01, so the method and every threshold here are Orchestrator rulings (`plan.md` O53, O54), except TH-3's floor, which is the user's Q26 ruling, and the keep rule MM-18 applies, which is the user's standing rule of 2026-11-01 (`plan.md` O64). The ids MM, HP, and TH are fixed for the campaign.

### Host profile

The method-bearing readings of the measuring host, read on 2026-11-01 by the host survey and the measurement calibration (`plan.md` O53); the commit that records O53 carries the survey's processor, power plan, GPU, memory, and toolchain readings in its message, and `package.json` holds the installed versions. A slot on another host reads its own profile before its first cell, and its readings never mix with these.

| Fact | Reading |
| --- | --- |
| Logical processors | 16, on 8 cores, so one busy logical processor reads 6.25% of other load (HP-3, HP-4) |
| Clock ramp from idle | about 33% of steady work in the first 25 ms window, steady after about 75 to 100 ms (one run) |
| CPU timer | `process.cpuUsage` steps 15 to 16 ms, median 16 ms over 200 steps |
| Wall timer | `performance.now` steps 0.1 to 1.2 µs, median 0.2 µs; `process.hrtime.bigint` steps 0.1 µs |
| Within-process wall noise, MAD-based | 0.31% to 1.77% across rc-a3's ten cells, 1.77% at the 13 ms control cell |
| Within-process CPU noise, MAD-based | 11.8% at 391 ms, 3.4% at 1359 ms, 0.55% at 126 s |
| Between-process wall spread | three processes of a 22 ms reference kernel: medians 22.43, 22.56, and 22.78 ms, wall CV 1.05% to 2.38% per process |
| Forced garbage collection | raised the spread of the 22 ms kernel (MAD 0.72 ms against 0.14 to 0.21 ms) and moved an allocation-heavy workload's median by 48% |
| Other load | rc-a3's quiet baseline 4.36%, per cell 0.04% to 4.21%; about 7.1% with orchestration lanes active |
| GPU memory in use | 0 MiB with no model loaded, the baseline of HP-2's bound |

### Budgets

Each threshold maps to one of these budgets.

| Budget | Value | Applies to |
| --- | --- | --- |
| Server overhead floor | at most 5% of the subject model's mean agent-call wall: 660 ms at 4B (the c1 mean of 13206 ms); the 2B wall is rc-a9's to read | serial work before the model call: `select`, and hydrate per request |
| Long task | 50 ms per main-thread task | synchronous work in a page |
| Device factor | a `src/core` path that can run in a page reads the page budget divided by 4, so 50 ms becomes 12.5 ms on this host; the factor is Lighthouse's documented 4x default mobile CPU slowdown, the recorded source (`plan.md` O55) | every `src/core` path that can run in a page |
| Frame | 16.7 ms at 60 Hz | streaming and per-delta work in a page |
| Smallest gain worth having | 16 ms on a server path; about 4 ms on a page path after the device factor | the absolute floor beside a relative gain |

### Instrument

- MM-1. Gate on the wall time of the timed region: `performance.now()` at the region's start mark and end mark (rc-a3's marks: the `start` event to the first `select` event). Report `process.cpuUsage()` user plus system over the same region beside it only where a cell's median is at least 500 ms, because the CPU timer's quantum is 16 ms. Under Vitest's `threads` pool the CPU reading is process-wide, the runner's main thread and V8's helper threads included. Apply the preemption flag (wall over CPU above 1.10 reruns the cell one time) only to cells whose CPU median is at least 1600 ms; under that, HP-4 and MM-8 detect interference.
- MM-2. Read the region marks the bench records itself, never tinybench's own timing, which covers the whole callback; report tinybench's mean and relative margin of error and never gate on them. A bench is a `*.bench.ts` file under the `probe (bench)` project, run through `npm run test:bench` (`@orkestrel/scaffold` `.claude/rules/tests.md` § Probes, cited until `@orkestrel/scaffold` 0.0.123 carries the amended bench text; `plan.md` O54). Set tinybench to `time: 0`, `iterations: n`, and `warmup: false`, run MM-7's warmups in the bench, and check tinybench's loop condition on that pair before the brief fixes it.
- MM-3. When a region's median wall is under 10 ms, time K back-to-back calls as one reading, with K times the median at least 100 ms, and divide. A page reading holds at least 10 ms of work, because a page's `performance.now` steps 100 µs without cross-origin isolation.

### Isolation and order

- MM-4. Run one process per cell, a cell being one build, arm, and size: the runner, a TypeScript script launched through the dispatch skill's launcher, starts one Vitest invocation per cell, selected by test name. rc-a3 ran its ten cells in one process; its readings stay valid as the baseline.
- MM-5. Seed once and hydrate per process: build each seed one time per lineage with the before build, write its snapshot under the unit's folder in the probe directory, and hydrate it in every process of both builds. Both builds produce the same selection digest from it before any timing counts; that check is also the replay check.
- MM-6. Interleave builds in one slot: with m processes per build, alternate them (A B B A at m = 2, A B B A A B at m = 3), so drift across the slot lands on both builds. A ratio gate reads its before build in the gating slot beside the after build; a before reading taken in an earlier slot is a trigger reading, a cross-check, or a sensitivity control, never the denominator of a ratio gate. At the gating slot's start, the Orchestrator copies the checkout's source and tests into the unit's folder in the probe directory three times: `after/`, the working tree; `before/`, the same copy with every `src/` file the unit changed read from the unit's launch commit and every `src/` file it added left out; and `replica/`, a second copy of `before/` at a separate path for MM-13's A/A. A live neighbour's edits therefore sit identically in every build. Every live writer pauses at a green phase boundary for the length of the slot, leaving `src/core`, `tests`, and `guides` untouched, so no copy holds a half-written file; the Orchestrator records a `git hash-object` digest of each live writer's diff at slot start and end, and a slot whose digest changes is void and reruns (`plan.md` O54, O55); each copy resolves the checkout's installed dependencies; the slot record names each tree's digest; and the unit's brief settles how the runner points the bench project at each copy and checks it in the before slot.

### Warmup, garbage collection, samples

- MM-7. Warm up in each process until at least 1 s of cumulative region time and at least 2 iterations have passed, capped at 30; a cell of 1 s or more keeps rc-a3's 2 warmups. The quiet-baseline wait runs before the warmups, never between the warmups and the samples, because the clock falls to about 975 MHz at idle.
- MM-8. Never force garbage collection, in any arm. Report each cell's maximum over its median; a cell with more than 15% of its samples over 1.25 times its median reruns one time.
- MM-9. Choose m processes per build and n samples per process from § Detectability so the threshold is at least the smallest readable difference there; n is at least 7. A cell over 60 s per sample that sits more than 10 times from its threshold can drop to n = 3 with 1 warmup. Every ratio gate at or under 1.10 runs at least 2 processes per build, interleaved A B B A, and every 1.05 gate at least 3, interleaved A B B A A B.

### Statistic and verdict

- MM-10. Use medians, never the mean and standard deviation: per process the median, minimum, maximum, and c = 1.4826 × MAD / median; per cell the median of the process medians.
- MM-11. Report a comparison as the ratio of cell medians with its 95% interval: at 6 or more processes per build, a seeded bootstrap of 10000 resamples over processes and then samples within each process; at 2 to 5, a t interval on process medians with 2m − 2 degrees of freedom; at 1, the interval holds within-process noise only, so a gate read at one process per build sits at least 3 times the one-process readable difference from its threshold, and a keep reading against no change at one process reads at 3 × c_diff, because § Detectability's table sets that readable difference at 3 × c_diff and no second factor of 3 applies against a ratio of 1 (`plan.md` O77). Fit a slope as ln(wall) on ln(size) over the stated sizes; a slope from single-process cells has a standard error of about 0.022 at n = 7 and 0.019 at n = 15, so a slope reading is decisive at least 0.065 from its threshold and `marginal` nearer.
- MM-12. Read one of four verdicts. `meets`: the interval's unfavorable end clears the threshold. `marginal`: the point clears and the interval straddles it; rerun with m doubled, and a second `marginal` reads as that threshold not met, and MM-18 rules on what the change keeps. `misses`: the point does not clear. `contested`: a cell broke HP-4 twice; no verdict. A slot whose A/A trips MM-13 reads `unreadable`, apart from every verdict.

### Controls

- MM-13. Run one A/A pair in every comparison slot: the same build in two process sets at separate paths, interleaved like the real comparison. Its point sits within 2 to 2.5 times the measured c_diff and its interval includes 1. An A/A whose spread puts 3 times c_diff over the threshold makes the slot `unreadable`; the observed spread re-derives c_b for the slot, and m rises when it reads over the table's c_b. A brief that fixes m at the cap as a stated departure from MM-9 states its own readability bar, tied to its keep, before the run, as rc-u19's does (`plan.md` O70).
- MM-14. Prove the bench can fail before trusting a pass. Where the before build reads `misses` on the metric a gate or trigger reads (rc-a3b's slope gate; rc-u21's case A slope, which TH-4's trigger reads), that reading is the control. Otherwise inject a busy wait of the threshold plus 3 times c_diff into the timed region and require `meets` as a change, and one of the threshold itself and require at least `marginal`. Every 1.05 non-regression gate gets its own injected arm, sized from the slot's measured c_diff: about 7.3% at m = 3 on the provisional c_b of § Detectability, and about 9.6% at m = 4 on the pilot's. Those sizes assume a z interval. Where a gate reads a t interval (MM-11, 2 to 5 processes per build), an injection of the threshold plus 3 times c_diff reads `meets` only about 60% of the time at m = 3 and one of the threshold reads `marginal` or better about 50%, so a brief sizes its arms on the quantile q of MM-11 (t(0.975, 2m − 2) at 2 to 5 processes per build, 1.96 at 6 or more) and on c_diff and the before median from its own pilot, in two forms (`plan.md` O70). On an improvement target with threshold T and before median M, the arm D1 = T + (q + 1.3) × c_diff(m) × M must read `meets` as a slowdown, about 90% power, and the arm D0 = T passes when its interval on the slowdown includes T. On a 1.05 non-regression bar with control median M_c, the arm E1 = (0.05 + (q_c + 1.3) × c_diff_c(m_c)) × M_c must read `meets` beyond 1.05, the interval's lower end over 1.05, and the arm E0 = 0.05 × M_c passes when its interval on its ratio includes 1.05. Each arm is sized on its delivered size under MM-17; an arm that under-delivers takes one recalibration and one rerun, and a second failure, or a failure of an arm sized for 90% power at full delivery, voids the instrument and stops the unit before any source edit for the Orchestrator to rule. A brief with two arms sized for 90% power states that a sound instrument stops it about one time in five. A gate whose cell times its change synchronously inside the timed region can state a departure from this bullet with that reason, as rc-u19's hydrate bar does (`plan.md` O70).
- MM-15. Keep the mutation probe on the load-bearing line of § Cheap-first order; a bench never replaces it.
- MM-17. Size an injected sensitivity arm by what it delivers, never by its nominal spin. In a paced asynchronous case, part of a spin overlaps each round's waiting time and the arm under-delivers: rc-u21's first comparison group injected a nominal 5.0% that delivered +2.36% and read `meets`, and a nominal 7.4% that delivered +5.13%, each read on the median of process medians, so the group read `unreadable` with a sound instrument (`plan.md` O60). Calibrate S and T on their effective sizes from the slot's own medians: the spin is the target share times the before build's cell median plus the measured overlap loss, read as the largest loss estimate on the gate statistic (rc-u21: S = 0.05 × 3.8608 + 0.0958 = 0.2888 ms and T = 0.075 × 3.8608 + 0.0958 = 0.3853 ms), and rerun the group one time under MM-13's `unreadable` rule. The loss is no constant: the 0.055 to 0.097 ms rc-u21's first group read did not recur in its reruns, where S delivered +7.6% and +7.4% of the before build's median against its 5.0% target and T +9.5% and +10.5% against 7.5%, so each brief measures the loss in the slot that uses it and never carries a figure over from another slot.

### Keep and revert

- MM-18. Every brief launched after the keep rule of 2026-11-01 writes its miss and revert clauses under the keep rule of `tenets.md` § Scope (`plan.md` O64), before its before run. A gain reads shown when the interval on the case the change targets clears no change, a ratio of 1, in the faster direction, whatever its verdict against the improvement target, and not shown when the interval includes no change. A shown gain keeps the change, and a missed improvement target is recorded as read. A gain that is not shown keeps the change only when the brief names a merit beyond speed before the run (correctness, bounded retention, or a simpler reading for a developer or a small model); a pure speed change whose gain is not shown reverts (`@orkestrel/scaffold` `.claude/rules/quality.md` § Performance). A miss of a no-regression bar on a case users hit reverts the change in every case. Shown and not shown read the interval against no change, never against a threshold: a second `marginal` against an improvement target (MM-12) still keeps the change when its interval clears no change. How a second `marginal` against a no-regression bar reads is fixed in the brief before its before run, as TH-2 fixes its marginal rule, and a brief that fixes none takes that reading to the Orchestrator to rule. No bar moves after the data. A change that is mixed, faster on some cases and slower beyond its no-regression bar on a case users hit, reverts or goes to the user (rc-ct1, `plan.md` Q28, O62).

### Detectability

The noise of a before and after comparison with m processes per build and n samples per process is c_diff = sqrt(2 × (c_b² / m + 1.57 × c_w² / (m × n))), where 1.57 is the variance cost of a median against a mean; this is a derivation, not a cited formula. The measurement plan set provisional values before the pilot: c_w = 1.5%, the within-process wall noise read as the worst of rc-a3's cells (the consultation's recomputation read 1.77% at the 13 ms control cell, which MM-3's repetition covers), and c_b = 0.8%, from three processes of the 22 ms reference kernel, its 95% interval from about 0.42% to 5.0%. The A/A pilot read c_w 0.94% and c_b 2.16% on the control `select` at 1600 messages, and the table is rewritten from those values; a workload the pilot does not run reads its own c_b under MM-13.

| m | n | t(0.975, 2m − 2) | Smallest readable difference, on the pilot |
| --- | --- | --- | --- |
| 1 | 7 | none; 3 × c_diff | 9.4% |
| 1 | 15 | none; 3 × c_diff | 9.3% |
| 2 | 15 | 4.30 | 9.4% |
| 3 | 15 | 2.78 | 5.3% |
| 4 | 15 | 2.45 | 4.6% |
| 5 | 15 | 2.31 | 4.1% |
| 6 | 15 | 2.23 | 3.8% |

- A threshold is readable when it is at least the larger of 3 and t(0.975, 2m − 2) times c_diff, because MM-11 reads 2 to 5 processes per build with a t interval on process medians; on the pilot's values a 1.05 gate is not readable at m = 2 or m = 3 and is readable from m = 4, so every 1.05 gate runs at m of at least 3 (MM-9), and at least 4 where the pilot's c_b applies. A true effect needs about the threshold plus (t + 0.84) times c_diff to read `meets` at 80% power.
