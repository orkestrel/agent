# Sustained-work comparison requirement

The user requires a final records-versus-aggregate comparison on very long conversations and sustained work before the decision to adopt aggregates. This extends the experiment exit criterion. The accepted matrix, implementation proofs, and blind audit remain required.

After the matrix, run a separate held-out workload frozen before either arm receives its evaluation questions. Use the verified agent main build for records and the same build plus the maintained aggregate harness for aggregates. Record exact commits, hashes, role settings, model digests, budgets, tools, seeds, and corpus identities. Disclose every required difference between arms. Compare matching model and thinking configurations.

Run continuous conversation and work history through each arm without resetting ledger or aggregate state between checkpoints. Grow history beyond the decision window while carrying unfinished tasks, tool outcomes, corrections, withdrawals, revised decisions, and dependencies on older evidence. Freeze workload size, checkpoint schedule, tools, quality rubric, resource caps, and stopping rules before evaluation. Score held-out goal evidence and concrete work products. Preserve actual provider requests, ledger selections, maintenance events, failures, recovery, usage, and elapsed time.

Score quality blind to arm identity, with ambiguity bounds. Report quality by history length and checkpoint: correctness against active facts, completed work, outstanding obligations, revised facts, and recovery from missing context. Report maintenance cost and total decision and judge cost separately. A length or resource refusal is an invalid configuration or explicit completion limit. Do not increase resources after reading evaluation quality.

The final recommendation must consider this comparison and the matrix together. Summary appearance, cold-build success, and short-scenario scores cannot close the adoption criterion. Preserve inconclusive and negative results. The blind design opinions will supply a bounded implementation specification before workload authoring or evaluation.
