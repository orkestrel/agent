# Qualify full view against observed allocation

Keep the finite history calculation, but stop using its requested window as evidence of service capacity. Freeze a separate effective qualification ceiling before the development trajectory, bind service allocation and non-truncation evidence to each full-view request, and qualify only complete observed trajectories. A calculated envelope larger than the service allocation does not by itself establish infeasibility. This is a contract proposal, not an accepted implementation or authorization to run inference.

## Minimal contract

Use the existing matrix manifests, `RefitFile` hashes, transport seam, and request sequence identities. Add no discovery framework. Keep the following quantities distinct.

| Quantity | Contract |
| --- | --- |
| Calculated envelope `B` | Retain `MatrixBound.window` and its inputs as planning evidence. It is an estimate, not observed capacity or exact tokenization. |
| Requested window `W` | Retain `MatrixBudget.window` as the exact requested `num_ctx`. Validate equality at every applicable wire request. The minimal proposal preserves its value; it does not prescribe lowering the oversized request. |
| Effective qualification ceiling `C` | Add `MatrixFull.capacity: { window, evidence }`, with `window=C` and `evidence` a hashed observation artifact. Freeze a positive safe integer greater than the unchanged reserve before preflight; require `C <= W`. This is the maximum window allowed for this qualification, not a claim about the model's ultimate capability. |
| Serving allocation `A` | Add optional request evidence `allocation: { window, runner, evidence }`; absence prevents full-view qualification. `window=A` must be a measured per-sequence allocation, with service/model digest and request association in the hashed artifact. Require `A >= C` for each full-view decision request. A smaller observed allocation invalidates the frozen qualification; do not silently lower `C`. |
| Actual usage `P`, `O` | Keep the raw response and derived `prompt`/`completion`. Require finite nonnegative integer counts from a completed response, completion within the unchanged reserve, and `P + O < C`. Equality is invalid under the matrix's boundary rule. Missing usage remains unknown. |
| Model maximum metadata | Retain any observed training-context or maximum metadata in the evidence artifact, with its source and meaning. It can inform ceiling selection but cannot substitute for `A`. Do not add a hardcoded family maximum or require an unmeasured universal maximum. |

Add optional `MatrixRequest.integrity: { truncated, evidence }`. Accept `truncated=false` only when the referenced service observation establishes no input removal or context shifting for that exact request, including prompt ingestion and generation. Explicit truncation invalidates the trajectory. Missing, ambiguous, or unbound observations leave qualification unresolved. A client `truncate=false` option, low returned usage, or a log field whose coverage has not been verified cannot supply that fact.

The observation artifact must bind the frozen model digest, daemon/build identity, service session, runner identity, request sequence and body digest, raw evidence location, and association method. Reuse `RefitFile` for custody. Preserve each raw observation rather than recording only a pass boolean. A role that requests a smaller context can reload the runner; never extrapolate the opening allocation over later tool continuations or recovery. Retain all role requests and calibration observations, but apply the full chronological-history requirement to the decision requests that consume that history. Validate other roles against their own unchanged settings.

Strengthen request custody at the existing fetch seam: retain the exact serialized body string in addition to its parsed object, and bind both to the sequence. Before sending a full-view decision body, compare its complete ordered messages with a retained boundary snapshot derived from the conversation, system/instructions, and the existing provider projection. Preserve tool arguments/results and recovery additions. Reject omitted, duplicated, reordered, or rewritten history; do not use phrase presence, an estimate, or message count as equality. Record unsent observations separately. The expected history must derive from the conversation independently of the selected tail. Use the vendored `mapMessages` projection rather than inventing wire rendering. See `.orkestrel/agent/instruments/harness/vendor/ollama/index.d.ts:279`, `.orkestrel/agent/instruments/harness/vendor/agent-0.0.30-trimmed/index.d.ts:235`, and `.orkestrel/agent/instruments/harness/bench5/Driver.ts:1281`.

## Phase order and finite qualification

Apply the contract in this order.

1. Preserve the predecessor freeze, failed trajectory, request/response evidence, bound, diagnostics, and costs. Implement and prove the observation/custody checks offline. Produce a successor source freeze because source and build identities are part of the configuration.
2. After separate authorization for service observations, establish the request-to-runner association and non-truncation signal. Freeze `C` and its evidence before the full preflight. Historical allocation can motivate the candidate ceiling; it cannot establish a successor request's serving allocation.
3. Write the retained `B`, requested `W`, unchanged reserve/settings, finite trajectory limits, and a finite wall deadline before requests. Preserve the existing goal, turn, per-request, and recovery bounds; the launcher deadline bounds total elapsed work. No quality outcome chooses resources, extra attempts, or a larger window.
4. Run the existing complete unscored copy-1 protocol with complete wire history at every decision boundary. Validate custody, allocation, non-truncation, usage, completion reason, and the whole trajectory before accepting the full manifest. `B > C` alone neither blocks that bounded empirical attempt nor disqualifies a complete observed trajectory that fits.
5. Require the accepted full manifest and its evidence downstream. Reapply the same checks to every evaluation trajectory; copy 1 does not prove all future histories fit. Preserve resource-invalid, evidence-unqualified, and operational-fault outcomes separately from answer quality. Never convert an unknown allocation into an eliminated model configuration.

This qualification establishes that the observed complete trajectory fit the frozen ceiling. It does not establish a worst-case guarantee for every possible generated history. Calibrated pre-send estimates remain estimates; never trim messages or declare measured infeasibility from an estimate exceeding the ceiling. An actual overflow or truncation invalidates the affected trajectory. A transport failure remains operational even when its text mentions capacity; the existing `readRequestOutcome` precedence preserves that distinction. See `.orkestrel/agent/instruments/harness/bench5/matrix/helpers.ts:410` and `.orkestrel/agent/instruments/units/aggregates/matrix.md:33`.

An unchanged fresh retry can measure recurrence of the operational failure under the predecessor settings. It cannot qualify full view under this contract because the predecessor implementation lacks the required checks and evidence. A successor source freeze can qualify after its bound capacity observations and complete preflight pass, while retaining the same decision sampler, thinking policy, reserve, initial records plan, chronology, recovery, and evaluation population. Any later choice to change requested `W` is an explicit resource revision, not an unchanged retry. Source hashes already invalidate a changed configuration; see `.orkestrel/agent/instruments/harness/bench5/matrix/helpers.ts:87`.
