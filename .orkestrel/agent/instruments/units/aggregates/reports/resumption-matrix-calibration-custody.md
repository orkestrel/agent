# Calibration custody ruling

Use the existing qualified matrix/refit operators for the remaining preparation cells. Share an accepted fit across decision-thinking settings when the fixed summarizer, judge, source, settings, and seed identities match. Do not regenerate calibration merely because decision thinking changes. The special unqualified development policy cannot generally serve the remaining cells: it binds the predecessor's decision identity and q2-specific refusal and budget values. That restriction is an operator limitation, not evidence that those models cannot run.

This report is source and retained-metadata analysis. No model calls, service queries, tests, builds, source edits, answer-quality inspection, or Git mutation occurred. The only authored file is this report. No runtime proof is claimed.

## Separate the contracts

The recorded plan explicitly shares a fixed summarizer's calibration across decision-thinking conditions; it separately requires cell-specific reserves, pilots, full preflights, and result identities. See `.orkestrel/agent/instruments/units/aggregates/matrix.md:25`, `.orkestrel/agent/instruments/units/aggregates/matrix.md:31`, `.orkestrel/agent/instruments/units/aggregates/matrix.md:41`, and `.orkestrel/agent/instruments/units/aggregates/matrix.md:67`.

The implementation supports that sharing. A successful refit writes only summarizer, judge, files, settings hash, and seed hash into the fit's matrix identity. Aggregate admission compares those fields, with no decision role or decision-thinking comparison. See `.orkestrel/agent/instruments/harness/bench5/refit/Refit.ts:722` and `.orkestrel/agent/instruments/harness/bench5/matrix/helpers.ts:603`.

Fit creation must still use the exact freeze used for generation: `Refit.#fit` compares the entire generation matrix to `--frozen`. Fit under the original calibration freeze, then share the resulting accepted fit; do not relabel the generation or refit it under the other thinking freeze. See `.orkestrel/agent/instruments/harness/bench5/refit/Refit.ts:687`.

Changing decision thinking does not change the seed-only calibration generation request distribution in this implementation. Generation uses corpus contexts and prompts, the model-key settings, and a summarizer with `think:false`; the cache lineage binds summarizer, judge, source, and seed. Decision thinking changes the enclosing generation freeze metadata. It does change the later live decision requests and potentially the subsequent history; seed calibration does not certify that diverged history. See `.orkestrel/agent/instruments/harness/bench5/refit/Refit.ts:470`, `.orkestrel/agent/instruments/harness/bench5/refit/Refit.ts:498`, `.orkestrel/agent/instruments/harness/bench5/refit/Refit.ts:519`, `.orkestrel/agent/instruments/harness/bench5/refit/Refit.ts:655`, and `.orkestrel/agent/instruments/units/aggregates/matrix.md:53`. This is a source-derived statement about inputs, not a claim that independent stochastic runs produce identical outputs.

Source identity is stricter than scientific role equivalence. `readFrozen` requires the retained source population to equal the actual source population; accepted fits require exact file identities. Consequently the l9 failed diagnosis cannot become a qualified fit on the amended source by copying or changing metadata. Fresh qualified preparation requires the final source freeze, even for q2. The existing development bridge is the separately bounded historical-source exception. See `.orkestrel/agent/instruments/harness/bench5/matrix/helpers.ts:306`, `.orkestrel/agent/instruments/harness/bench5/matrix/helpers.ts:465`, and `.orkestrel/agent/instruments/harness/bench5/matrix/helpers.ts:611`.

## Identify the development blocker

The special policy requires `agree:0.67`, `change:0.56`, and the declared majority-grid selection name; it forbids accepted/separated claims. `readDevelopment` requires an unequal successor freeze hash but equal predecessor/successor key, think, decision, summarizer, judge, seed, settings, configuration, and deployment. It permits only its enumerated source changes. See `.orkestrel/agent/instruments/harness/bench5/matrix/types.ts:105`, `.orkestrel/agent/instruments/harness/bench5/matrix/validators.ts:124`, and `.orkestrel/agent/instruments/harness/bench5/matrix/helpers.ts:430`.

The refusal gate requires `accepted:false`, strict cutoff `0.93`, the exact diagnosis preparation references, and `generation.matrix === predecessor`. The l9 fit-v3 metadata has that failed cutoff and q2-think0 identity. The gate further requires accepted predecessor records at `buildBudget(512)`, a refused single-attempt full manifest, and exact expanded budget `{reserve:512,window:1068663,ceiling:262144,predict:0}`. Therefore even a fresh same-cell failed fit with another cutoff or measured budget cannot generally enter this policy. See `.orkestrel/agent/instruments/harness/bench5/matrix/helpers.ts:489`, `.orkestrel/agent/instruments/harness/bench5/matrix/helpers.ts:507`, `.orkestrel/agent/instruments/results/l9/calibration/q2/fit-v3/diagnosis.json:2`, and `.orkestrel/agent/instruments/results/l9/q2-think0/freeze/manifest.json:7`.

No alternate admitted unqualified matrix phase appears in the deciding entry: it exposes freeze/resource/full/pilot/plan. `readExecution` admits development through this policy, while every other aggregate execution requires an accepted fit. Changing a CLI flag or using an unfrozen refit does not satisfy either gate. See `.orkestrel/agent/instruments/harness/bench5/matrix/Matrix.ts:77` and `.orkestrel/agent/instruments/harness/bench5/matrix/helpers.ts:593`.
