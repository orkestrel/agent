# Aggregate admission verification

The revised admission mechanism passes independent offline verification. The final run reports 320 of 320 tests passing across 76 suites, with no skipped, cancelled, or pending tests. Scoped lint, formatting, TypeScript, and whitespace checks exit 0. This accepts the offline mechanism; calibration and live feasibility remain open.

Both arms use the same default ledger shares. A summary is admitted against the complete built request, including calibrated overhead, within the declared 2560-token ceiling and block allowance. Cuts remove whole summary entries and preserve selected evidence. Empty treatment emits no heading. A failed fit refuses execution.

The harness clears stale treatment for answer selections through the public context/provider boundary. The proof compares the turn-time estimate with the actual provider request. The wire report checks every agent completion, including calibration and continuations, for usage evidence, completion reserve, length termination, and context exhaustion. Later growth is a stopping invariant; first-request admission does not predict every later request.

The held-response integration replays the archived control's complete 40-request sequence for control, empty, rejected, and fully cut treatment. All 160 request bodies match the unnormalized serialization of the archived recorder bodies, including the initial g01 selection and seed 33. The archive stores parsed request envelopes; this comparison does not claim access to historical HTTP request octets. Independent review and root each reread the retained bodies and hashes. The source test and committed archive reproduce this proof without a live service.

Independent review found that duplicate summary blocks could support their own removed tokens, and an IDs-only entry could count as prose exposure. Root accepted these bounded evidence-validator defects. The successor requires one recorded summary block across system messages and consumes the optional IDs header before checking for prose. Focused tests changed from 2 passing and 4 failing to 6 passing. Adjacent valid bodies remain accepted; a single unsupported body still fails lexical containment. These malformed forms were not observed from the Driver.

The final verifier command runs every `bench5/tests/*.test.ts` file through the canonical launcher with a 120-second cap. The run measured 22,985 ms including launch and 22,849 ms inside the test runner. Its file census contains 15 paths; the earlier verifier report's stated 14 paths was a counting error, while its retained census also contains those 15 paths. The final owned source population is 16 files and its hashes remain unchanged across verification. See [the verified source hashes](admission-hashes.json).

The retained temporary evidence is `aggregate-admission-final-report.md` with its gate logs, the independent `aggregate-admission-review-report.md`, the bounded `aggregate-wire-successor-report.md`, and the root reproduction `aggregate-wire-root.log`, all under the session worktree's ignored `tmp/units`. Source mutation controls for admission, answer cleanup, and failed-fit refusal each failed under the breaking edit and passed after restoration. Original pilot evidence and fit remain unchanged.

Lexical containment proves copied identifiers, numbers, and candidate names occur elsewhere in the actual request. It does not prove every summary relationship occurs there. AGREE remains the separate source-support check. Held responses prove request identity and boundary behavior, not improved generation or useful exposure.
