## Execution

Read every complete candidate in context. Divide it into material propositions; preserve attribution, entity, timing, conditions, negation, and completion status. A request to act does not prove completion. A superseded value must not become current. Resolve aliases only from supplied sources. Do not add world knowledge or favor useful-sounding summaries.

Use supported when every material assertion is entailed, contradicted for a definite conflict, unsupported for a definite added assertion, and ambiguous for materially unresolved meaning or evidence. A supported candidate requires every proposition supported. Explain mixed cases and choose the substantive nonpositive verdict; root adjudicates uncertainty. Wording alone is not a factual defect. Do not invent a contradiction merely because the candidate paraphrases evidence.

Preserve each occurrence ID. Exact semantic duplicates may share analysis only after candidate, question, state, and sources equality is established. Component/revision/occurrence identities must not disappear from output. Compute item hashes as SHA256(JSON.stringify(parsedItem)) in original parsed property order. Use complete evidence, without truncation. Perform the assignment yourself and spawn nothing.

## Output

Write a JSON array, not an authority wrapper. Each entry is {id:string,item:string,verdict:'supported'|'unsupported'|'contradicted'|'ambiguous',propositions:[{text:string,verdict:the same union,evidence:string[]}]}. Each candidate has a nonempty proposition list. Each evidence entry is a bare exact contiguous quotation from a supplied source: no prefixes, ellipses, or explanatory commentary. Explain the source identity, missing entailment, or conflict in proposition.text or the report. For unsupported additions, quote the relevant actual source and say what it fails to establish; never invent a quotation describing absence.

Report input/output hashes, measured counts, verdict counts, exact duplicate-group method, and unresolved ambiguity. Emit no numeric judge score. Root owns adjudication, wrapper, and acceptance. Return the completed report path only after labels and checks close; send substantive progress meanwhile.

## Deviation contract

Stop for an incomplete packet or contradictory structural fields. Report expected, found, evidence, done or not done, and at most one hypothesis. Settle presentation in scope. Label semantic uncertainty ambiguous without seeking private data.

## Acceptance criteria

1. Check the supplied packet hash, shape, and measured census.
2. Analyze complete semantic groups independently and expand to every exact item.
3. Verify exact ID/hash bijection and literal quotations with a small read-only data check.

**Observations.** No gates or model calls. A missing semantic implication is not a structural error.

**Measurement.** The supplied conversation-derived support packet only. Report no task-quality or adoption conclusion.

## Review evidence

The immutable packet, independent proposition judgments, exact source quotations, and ID/hash coverage form the evidence. Root adjudication follows this independent return.
