# Reuse completed preparation baselines

Completed, accepted copy1 resource-records and full-preflight runs can serve as the disclosed baselines for the exploratory aggregate development run through the existing raw readers and accepted copy1 packet exporter. No duplicate records/full inference or source change is required by these interfaces. This conclusion is conditional on the existing custody, budget, initial-selection, and complete-goal checks passing on the actual retained runs; this unit inspected code and ran no artifact admission or inference.

Root's materialization instruction is explicit: set `withhold: true` in the aggregate development policy to preserve the accepted l13 policy. The closed report remains unchanged. The optional field's false default is not the selected policy; see the [withholding contract](.orkestrel/agent/instruments/harness/bench5/matrix/types.ts:127).

## Retain the existing checks

The existing direction requires copy1 exploration, independent caches, identical initial records selection, fixed budgets, every planned goal, majority actual-body exposure, and separate exploratory reporting. It does not require rewriting successful resource/full runs as development phases; see the [accepted matrix direction](.orkestrel/agent/instruments/units/aggregates/reports/resumption-comparison-completion-direction.md:17).

Use the accepted terminal resource attempt's records run and the accepted full manifest's preflight run at their original paths. Keep their execution phases `resource` and `full`, their status `complete`, and their existing cache and file hashes. The development policy already reads those exact runs: `readResource` checks the records phase, copy, freeze, ladder, and accepted terminal budget; `readAttempt` verifies the declared execution and evidence files and rejects accepted attempts with raw failures. See [resource custody](.orkestrel/agent/instruments/harness/bench5/matrix/helpers.ts:379) and [attempt custody](.orkestrel/agent/instruments/harness/bench5/matrix/helpers.ts:418).

For the aggregate execution, `readDevelopment` binds its paired budget to that resource budget and its expanded budget to the full bound recomputed from the same records trace. It checks the full attempt's copy, arm, frozen identity, resource reference, and expanded budget. A full refusal can satisfy development preparation, but it is not a completed accepted full baseline. Preserve that distinction; see [development resource/full checks](.orkestrel/agent/instruments/harness/bench5/matrix/helpers.ts:576).

Parse each run with `parseMatrixRun` and retain its actual phase and failures. This reader admits all of these phases, checks frozen and actual model identity, and requires rows and declared goals to equal the complete scenario order. Its terminal-status checks distinguish preparation from development. A nonempty failure list remains a failure; an exporter cannot repair it. See the [raw reader](.orkestrel/agent/instruments/harness/bench5/matrix/parsers.ts:32) and [complete trajectory/status checks](.orkestrel/agent/instruments/harness/bench5/matrix/parsers.ts:75).

Apply `listMatrixPairFailures(records, aggregate)` to the retained resource-records run and exploratory aggregate run. The helper accepts these phases because its input contract uses picks, gauge, and rows. It requires equal initial digest, tail, scale, and calibrated gauge, then checks paired scales. It does not itself check phase, frozen identity, budget, or complete goal coverage; those remain the preceding checks. Do not apply its records-selection equality requirement to the full-view arm, whose selection is deliberately different. The existing comparison consumer also calls it only for records/aggregate; see [pair helper](.orkestrel/agent/instruments/harness/bench5/matrix/helpers.ts:1299) and [existing consumer](.orkestrel/agent/instruments/harness/bench5/matrix/Comparison.ts:424).

## Preserve the continuation distinction

Operationally failure-free accepted baselines never exercised the XML continuation branch. `permitsContinuation` returns false outside development. The resource reader's feasibility check rejects the XML parser error as an operational fault. A completed accepted resource/full baseline can still contain an incorrect task answer; `success: false` alone is not that transport/parser fault and must remain available to the quality packet. See [phase-specific continuation](.orkestrel/agent/instruments/harness/bench5/matrix/helpers.ts:1092), [feasibility rejection](.orkestrel/agent/instruments/harness/bench5/matrix/helpers.ts:1122), and [row failure checks](.orkestrel/agent/instruments/harness/bench5/matrix/parsers.ts:67).

When the exact XML function/parameter error occurs in development, the helper permits only the originating goal's recognized parser response and local stopped follower, with other requests complete and capacity custody valid. Driver writes the failed row, clears that recognized stop, and reaches later goals. Resource/full execution does not clear it and terminates instead. See [exact parser signature](.orkestrel/agent/instruments/harness/bench5/matrix/helpers.ts:1057), [continuation restrictions](.orkestrel/agent/instruments/harness/bench5/matrix/helpers.ts:1098), and [Driver stop handling](.orkestrel/agent/instruments/harness/bench5/Driver.ts:1952), including [row preservation and continuation](.orkestrel/agent/instruments/harness/bench5/Driver.ts:2002).

Consequently, reuse of failure-free baselines does not assert identical continuation policies. If aggregate development exercises the extension, retain the failed goal and later outcomes and disclose the policy difference. If a resource/full baseline encounters that fault, it is not the completed accepted baseline described by this ruling; do not relabel it, synthesize later goals, discard its failure, or treat unattempted goals as served. No additional acceptance criterion is proposed.

## Use the accepted copy1 exporter

The accepted `packet-export.ts` takes repeated `--run` paths and checks `run.copy === 1`; it does not filter by execution phase. It imports no bench reader and therefore performs no independent matrix admission. It iterates the scenario's complete goal population, marks each goal `served`, `failed`, or `unattempted`, and exports replies and goal-local actions without dropping failed goals. See [copy1 input handling](.orkestrel/agent/instruments/units/aggregates/reports/resumption-l15-q4-thinking-quality/packet-export.ts:134), [goal/status export](.orkestrel/agent/instruments/units/aggregates/reports/resumption-l15-q4-thinking-quality/packet-export.ts:174), and [run arguments](.orkestrel/agent/instruments/units/aggregates/reports/resumption-l15-q4-thinking-quality/packet-export.ts:235).

The following existing invocation accepts the retained baselines and aggregate run unchanged. Uppercase arguments denote their absolute paths. `ABS_COPY1_JSON` must be the exact frozen copy1 scenario. `ABS_PACKET_OUT` must be an absent directory under `C:/Users/mikes/WebstormProjects/scaffold/tmp/units/` whose first relative path component starts with `aggregate-development-blind-packet`, as required by the exporter's output guard.

```text
node .orkestrel/agent/instruments/units/aggregates/reports/resumption-l15-q4-thinking-quality/packet-export.ts --copy ABS_COPY1_JSON --run ABS_ACCEPTED_RESOURCE_RECORDS_RUN --run ABS_ACCEPTED_FULL_PREFLIGHT_RUN --run ABS_AGGREGATE_DEVELOPMENT_RUN --out ABS_PACKET_OUT
```

The exporter records original run paths in private joins and hashes the scenario plus every input `run.json`, `rows.jsonl`, and `messages.jsonl`. Phase provenance remains bound through the hashed `run.json`; it is not exposed in the blind public packet. Preserve and disclose those original phases in the unblinded comparison record. See [private run joins](.orkestrel/agent/instruments/units/aggregates/reports/resumption-l15-q4-thinking-quality/packet-export.ts:214), [output guard](.orkestrel/agent/instruments/units/aggregates/reports/resumption-l15-q4-thinking-quality/packet-export.ts:227), and [input hashes and output artifacts](.orkestrel/agent/instruments/units/aggregates/reports/resumption-l15-q4-thinking-quality/packet-export.ts:258).

The standard `Comparison` CLI is not this route: it requires evaluation copies and phases, and its report selects a narrower goal population. See [evaluation-only admission](.orkestrel/agent/instruments/harness/bench5/matrix/Comparison.ts:65) and [goal filtering](.orkestrel/agent/instruments/harness/bench5/matrix/Comparison.ts:438). The existing copy1 exporter needs only the supplied retained run paths, not an implementation change. This addendum closes interface compatibility; it supplies no task-quality, runtime-admission, or endurance conclusion.
