# Child goals

`anatomy.json` holds the reviewed analysis that splits the 10 Larkspur goals into 25 child goals with one scored requirement each. `children.json` holds one entry per child (`id`, `parent`, `track`, `tests`, `request`, the `mechanical` rule set that `compileRules` in `../rescore.mjs` accepts, `patternLabels`, the `audit` questions a blind audit decides, `diagnostics`, `recordedReading`, optional `recordedMechanical` and `notExercised`, and `notes`). `fixtures.json` holds the reply texts with the verdict each must score; its `source` field says whether a text is constructed, quoted by the analysis, or a recorded reply. Run `node check.mjs` to compile every child's rules, score every fixture, and drop each `forbiddenPatterns` entry in turn to prove that a fail fixture then passes; it prints each failure and exits 1, or exits 0 when every fixture matches and no pattern is dead. The check also compares each pattern copied from `../scenario.json` with the scenario, so a scenario edit shows there.

`read.mjs` applies each child's rules to the recorded reply of its parent goal and writes one JSON line per run, copy, arm, and child. Run `node read.mjs --out ROWS.jsonl` to read the Qwen runs (`a1-control`, `a5-records`, `p1-ledger`, and the `v10` `f4`, `t2a`, and `t4` runs); add `--runs DIR[,DIR]` for another run directory, such as `../results/v11/g2-records-v1` for a second model family, and `--skip-recorded` to read only those. It prints a per-child, per-arm pass table and a diagnostic count table for each model and thinking setting, and exits 1 when a run file or a parent reply is missing. Each child reads the compound parent replies one of three ways (`recordedReading`). `full` applies every rule. `violations-only` (g05b, g06b, g06c, g06d, g08c, g08d) counts only violations, because the parent request never asks for the requirement its expected strings or presence patterns need. `parent-check` (g07b, marked `†`) replaces the child's expected strings with `recordedMechanical`, because "today" answers the parent's "by when" and the date forms are not required. Add `--full` to apply every rule, as a run of the split request needs. A `notExercised` entry (g05a) names a run and an audit item whose reply cannot show the requirement; the row scores `not-exercised` and leaves the pass denominator, and `read.mjs` reports an entry whose row fails for another reason or passes. A repeated goal in a run file is a problem and exits 1. The tools read the recorded results only and send no request.
