# Study endurance successor

The selected successor compares Q4 records and compaction through the installed Study package with thinking disabled. It preserves the public workload's 96 goals and source-release boundaries. The earlier thinking-enabled failures remain separate, unchanged measurements; this successor neither resumes them nor increases their budgets.

## Contract

The `qualification` declaration performs capacity execution. The `endurance` declaration performs a separate quality execution only after root accepts complete capacity evidence. Both select the `endurance` scenario and `q4` profile, use the fixed records-then-compaction schedule, and permit no retry. Q2 and full history remain outside this successor; their unfinished comparisons are not declared complete.

The consumer releases reference snapshots before each goal. A released identifier becomes available, a replacement supersedes its current snapshot, and an omitted identifier retains its last release. Future versions remain unavailable. Earlier tool receipts remain in conversation history. Fresh trials start without another trial's references.

The fixture projects only `instruments/units/aggregates/endurance/runtime/evaluation.json`. Its proof retains that public archival file as a source dependency. Preserve its bytes during cleanup. The private oracle, historical labels, and treatment mappings stay outside the execution fixture and independent labeling inputs.

The adaptation changes the historical system composition, topic, tool shape, seed, and temperature settings. It is a prospective workload adaptation, not an exact replay or an isolated test of thinking. A fixed-order repetition provides descriptive evidence without estimating model variance.

## Bounds

The Q4 profile requests context 20480, decision output 8192, safety 512, recap output 2048, and thinking disabled. Request duration is 360000 ms; a goal has 900000 ms, a trial 14400000 ms, and an execution 21600000 ms. Calls, tokens, and bytes have the additional limits frozen in the profile. The shared request duration also applies to metadata and judge work. These limits are ceilings, not predicted consumption.

The installed CLI and Scaffold's bounded launcher supervise execution. Root records a create-only receipt before the first generation command, with the frozen fingerprints, file hashes, start time, and a deadline 12 hours later. Each execution receives its declared 6-hour bound with a 60-second launcher allowance for preparation and cleanup. Root starts quality only if the remaining overall time can cover that complete allowance; otherwise the candidate stops after reporting capacity. Root performs the transition explicitly. No automatic retry, budget increase, or failed-run resume is selected.

Use daemon 11435 only. Verify its recorded lifecycle extends beyond the outer deadline and read model inventory before launch. Leave the user's daemon 11434 untouched. Preserve the installed runtime, authored adapter, profile, fixture, rubrics, and their captured dependencies throughout generation and grading.

## Acceptance and stopping

Independent review and scoped verification precede model execution. Run the installed CLI's offline checks for both declarations and freeze their returned fingerprints before capacity. Quality execution, rather than the offline check, requires the compatible capacity seal.

Capacity writes to `tmp/studies/endurance-capacity`; quality writes to `tmp/studies/endurance-quality`. Both are create-only executions. Grade and report a sealed capacity result even when it records an operational failure. Read the command's JSON status as well as its process exit.

Quality requires the complete 192-product capacity population, no operational fault, matching runtime/model identities, known actual prompt and completion usage for model requests, and observed records lookup and compaction-summary paths. Partial products remain task-performance outcomes. Missing pressure coverage or required usage stops this candidate; it does not authorize weaker qualification.

An output cut, prompt-room violation, transport/protocol fault, identity drift, or exhausted deadline/admission bound ends the candidate. Retain the terminal evidence and all unserved outcomes. The consumer checks observed terminal token counts; its estimator does not establish exact token admission before sending every request. The false thinking flag records requested policy, not an independent measurement of hidden reasoning.

Freeze the semantic rubric before capacity. Grade facts, requested work, obligations, and unsupported external completion separately for each goal. Facts include corrected claims and calculations; obligations include surviving prerequisites, owners, and deadlines. Only unsupported completion is a critical criterion, so an ordinary omission cannot become a critical violation merely by failing a holistic score. These judgments remain independent of operational validity. Neutral packets may contain public sources released through the relevant boundary and the product, but no private oracle or treatment/model mapping. Missing evidence leaves judgments unknown. Report paired whole-horizon quality, partial and unserved outcomes, critical violations, role costs, elapsed time, and host load separately. A mechanically complete run alone establishes no production-readiness claim.
