# Measured prefill policy review

**ACCEPT** the fixed 90000 ms metadata/auxiliary deadline for a new, explicitly recorded preflight attempt, identically across q4/q2 and their cells. Keep window 12288, decision reserve 4096, safety 512, decision/summary request deadline 180000 ms, goal deadline 900000 ms, whole-attempt deadline 1800000 ms, and existing call/token caps unchanged. This accepts a bounded timing policy; it does not certify capacity or a successful qualification.

The retained attempt supports a cold-prefill timeout diagnosis. `tmp/units/c1-capacity-initial-live/q4-records/run/run.json` reports an agent request wall of 30010 ms, terminal `Error: agent request deadline`, sequence 1, no turns, and no completed token usage. Its rows file is empty. The qualifier retained calls 8 and tokens 0, while the exact child exit is 3 with `expired: false`; the outer launcher recorded `capped=false duration_ms=31414`. Zero recorded tokens here means no completed usage report, not absence of model work.

The inspected daemon tail in `tmp/codex/c1-capacity-daemon.err` shows the first prompt at 9668 tokens in a 12288-token slot, beginning with no cached prompt. It reports model startup of 4.26 seconds, then 6144 prompt tokens processed in 23.95 seconds. The latest measured increment processed 512 tokens in 2.34 seconds. Cancellation released the slot at 6656 tokens with `truncated = 0`. Extending that latest observed rate over the remaining prompt gives roughly 44 seconds including startup; this is an extrapolation, consistent with root's roughly 45-second estimate, not a completed-prefill measurement. A 90-second bound supplies about twice that projected time and is a conservative finite next measurement under these observations.

`capacity.json` reports the intended q4 model/digest loaded at context 12288, with size and VRAM size both 3406833908 bytes. This supports resident model allocation at the requested context. It does not prove future output headroom, sustained throughput, q2 timing, or successful complete calibration. The calibration prompt size must not be treated as a decision prompt with its entire 4096-token output reserve; actual decision/summary admission and headroom checks remain authoritative.

The exact caveat is that the shared metadata flag also permits a stalled judge, flush, calibration, inventory, or other governed auxiliary request to wait up to 90 seconds, subject to the earlier goal/trajectory/series/outer deadline. Direct protocol, transport, usage, allocation, or output failures must still terminate immediately when observed. Applying one fixed bound to both models avoids changing policy after seeing a cell's result, but q2's sufficiency remains unmeasured. Host load during the failed prefill was not independently measured in this review, and throughput declined as the prompt grew, so 90 seconds is not a guarantee.

Freeze `--metadata 90000` into new manifests and record it in the new preflight plan before any calls. Preserve the failed attempt, its manifests, and the prior proof receipt byte-for-byte. Keep harness source and emitted build immutable; any revised launcher/qualifier policy must accurately record the 90000 ms value rather than claiming the old 30000 ms plan ran it. A failed new attempt remains failed and stops under the existing policy. This ruling authorizes no automatic retries, output-only escalation, context/output change, or reinterpretation of the first failure as a pass.

Only safe metadata, capacity records, launcher status, and the daemon tail were inspected. No oracle or product bodies were read, and no source changes, model calls, builds, or process actions were performed.
