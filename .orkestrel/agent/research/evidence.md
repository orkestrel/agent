## DeltaDB

The DeltaDB article (see [fine-grained version control for agents](https://delta.dev/blog/fine-grained-version-control-for-agents), dated 2026-10-29, no benchmarks) describes these mechanisms; C18 carries the verified subset, and `designs/records.md` § DeltaDB transfer rules on each.

| Mechanism | Description |
| --- | --- |
| delta log | a collection of CRDTs stored locally in SQLite and linked in a directed acyclic graph; a delta is the smallest unit of change; ancestry is stored apart from payload |
| frontier | the tip deltas; version vectors are rejected because they assume few long-lived actors; causal questions become walks over parent links |
| timelines | many frontiers on one shared graph; a subagent gets a timeline parked at the parent thread's frontier and merges later |
| reify at version | the nearest ancestor with a cached snapshot plus a replay of the deltas between; copy-on-write snapshots; loading a thread without replaying every delta is unsolved |
| primitives | a last-writer-wins register, an add-wins map, a buffer, and a worktree; the thread itself is modeled from them |
| blame | per-character blame is announced, not delivered; references anchor to deltas, not line numbers |
| sync and writer | a log-spaced version list over a socket, one durable object per thread, one writer thread on a frame budget |
