Rank the live hypotheses and experiments in this order. Hold other settings fixed, score first attempts separately from retries, and record which predicate clause changes.

1. **Save instructions cause lifecycle loops.** Replace the journey save sentence with: “Complete the requested browser actions and answer. Call save only when the user asks and a journey is recording. After save, edit, or replay succeeds, answer without saving again.” Predict deferred saving and fewer post-edit/replay loops. Separately change only the follow-up to: “If the journey is still recording, save it; otherwise confirm that it is already saved.” Predict removal of calls 9–11, with later loops potentially unchanged. Persistent loops refute sufficiency.

Predict room for an answer after J1’s eighth-call save; the listing failure remains. If generation 9 calls another tool, increasing the limit alone is insufficient. This cannot independently remove the opening partial failure. Keep the schema’s required argument during this experiment.

Predict Q1-shaped recovered attempts pass while successful unexposed actions still fail. If the returned text does not contain it and the footer names another line, continue reading from that line before answering.” Predict a second read from 61 and fewer fabricated answers. The seams ruled sound on this evidence are:

- Browser role checks, stale-reference refusal, corrective receipts, checkout submission, journey persistence, parameter binding, cart-step removal, and replay all work in the inspected successful paths.
- Requiring `from` is consistent between the advertised schema and runtime refusal. The prompt’s omission is a usability hypothesis, not a schema/runtime disagreement.
- Refusal counting resets after success and per user turn. Withdrawing definitions helps J1 answer, but is not a hard stop: J3 continues emitting calls afterward. `ended` therefore records scope withdrawal, not guaranteed termination.
- Attempt isolation and the shared retry/assertion predicate are consistent (`tests/setupStore.ts:1295`; `tests/service/browser.test.ts:44`). Retried success does not establish reliable first-attempt completion.
- The recorded 4B stumble identifies an oracle/completion mismatch. It does not establish a general rule that every failure shared by both models is a browser implementation defect.
