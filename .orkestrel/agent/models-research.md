# System One model evidence for agent studies

**Checked:** 2026-10-14. Research only: no models were run, downloaded, or benchmarked. Published scores and file sizes are source claims, not results on the GTX 1660 SUPER.

## Decision frame

The attachment is a useful lead list, not a ranking. It mixes typed decision models (d1, Kev, Wald, Julia, Laya, Tev1, Nimble, Clef), agent/chat models, and runtime-specific integrations. Keep judge and agent comparisons separate: the package judge returns typed probability distributions, while an agent must continue a conversation and request tools.

That split exists in the code. [`src/core/types.ts`](../../src/core/types.ts#L85) defines `choice`, `score`, and `noul` questions and probability answers; `JudgeRequest` says questions about a state are evaluated independently. The provider contract carries content, optional thinking, tool calls, and usage ([`src/core/providers/types.ts`](../../src/core/providers/types.ts#L30), `:361`). The current Mica adapter in `../ollama/src/core/OllamaJudge.ts:64` calls Ollama `/api/generate`, sends one question per call, forces one generated token, requests top logprobs, and derives calibrated distributions. `../ollama/src/core/OllamaProvider.ts:33` uses streaming `/api/chat` with tool definitions. Neither is the native Ollama `/v1/systemone` route: native System One returns typed answers directly and is supported by Ollama 0.35.0+, so the supplied Ollama 0.40.3 clears the version floor, but the current Mica adapter does not use it ([Ollama API](https://docs.ollama.com/api/systemone), [Ollama decision guide](https://docs.ollama.com/capabilities/decision)).

### Exclude or hold

- **Clef Flash:** Ollama documents native decision support from 0.35.1, but the Q4_K_M GGUF is 6.49 GB—over the card’s physical 6 GB before runtime memory or KV cache. Not a 6 GB candidate. [Ollama guide](https://docs.ollama.com/capabilities/decision), [GGUF](https://huggingface.co/ggml-org/Clef-Flash-GGUF)
- **Clef-27B:** its Q4 file alone is far above this GPU’s capacity. **Nimble-9B-v3** carries CC BY-NC 4.0 and is 9B; leave out of this bounded shortlist. **Tev1-4B-experimental** emits an option letter rather than a native typed distribution, and its model page says the fine-tuned-weight license is being finalized; exclude until that is settled. ([Clef](https://huggingface.co/Cloudflare/clef), [Nimble](https://huggingface.co/bespokelabs/Bespoke-Nimble-9B-v3), [Tev1](https://huggingface.co/togethercomputer/Tev1-4B-experimental))
- **Laya:** the attached 0.766 score belongs to the separately trained `laya-typed-decisions` model on its benchmark split, not the root/base model’s zero-shot score. Hold; the base is also a 512-context small model. [Card](https://huggingface.co/convaiinnovations/laya)
- **Strands Decider 2B:** Apache-2.0 and a relevant Qwen3.5 adapter, but its card reports question sensitivity under fixed state/options and uses a separate server; no GGUF/System One path was established in this check. Hold for a targeted robustness comparison. [Card](https://huggingface.co/StrandsAgents/strands-decider-2B-qwen3.5-v1-2610)

## Hardware and study limits

Registry and GGUF file sizes are weight-file sizes, not peak VRAM estimates. Runtime allocations, context/KV cache, Windows display use, batching, and other resident models are unmeasured. In static file-size arithmetic, Qwen3.5 4B (3.3 GB) plus Kev Q4 (3.03 GB) is 6.33 GB; Qwen3.5 4B plus Wald Q4 is about 6.01 GB. Neither is a simultaneous-residency plan. Qwen3.5 2B plus d1 Q4 is about 3.57 GB of files, which is only a plausible profile to measure—not a fit guarantee. Pin model digests, quantization, runtime version, context, and decision mode for any study.

Keep three profiles distinct: `agent/tool-use` through Ollama `/api/chat`; `judge/typed-decision` through either current Mica or a confirmed native System One adapter; and `mixed-residency` only if the study actually requires both models loaded together. A serial profile avoids assuming both models reside at once.

## Bounded comparison proposal

1. **Agent first:** compare pinned Qwen3.5 4B, Qwen3.5 2B, and Llama 3.2 3B tags on the same read-only tool fixture and task context. Record completion, tool-name/argument validity, unnecessary calls, tokens, cold/warm latency, and peak VRAM. Keep context small and matched.
2. **Judge next:** compare existing Mica against Kev Q4 native System One. Use the same held-out labels and score decisions plus class-level errors and probability calibration. Add d1 only once its exact local adapter is established; add Wald only if a second native-typed challenger is worth the separate server/mode complexity. Julia can be a cheap CPU floor on narrow taxonomies.
3. **Fixtures:** (a) message taxonomy—constraint, correction, decision, quote, task association, unclear; (b) paired arrivals—extension, replacement, confirmation, conflict, unclear, including negation/polarity and quoted statements; (c) lookup with a correct passage, distractors, and “none”; (d) continuing work with preserved constraints and a read-only lookup tool. Measure false supersessions separately from missed updates, plus lookup false hits and tool-call errors. Do not tune on the held-out cases.
4. **Only then test residency:** measure the selected agent/judge pair concurrently if a study needs both hot. Record peak VRAM and failure behavior on this exact host; file arithmetic alone cannot answer it.

No candidate has been established as a local winner. The smallest useful starting study is Qwen 4B/2B/Llama 3B for agent tool use and Mica/Kev Q4 for typed decisions, with d1/Wald gated on confirmed runtime integration.
