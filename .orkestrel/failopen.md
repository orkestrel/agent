# Fail-open rulings by package

This record rules on refuse-by-default boundaries and package fixes as of 2026-11-04.

Vocabulary follows `semantics.md`: a door runs `explain` (an `explain` fault refuses), then `audit` and refuses `extra`, then refuses an audit at `FAULT_LIMIT`, then refuses a `variant` or `oneOf` fault, then `parse`; a refusal carries `AuditFault` values in `context.faults`. A foreign interface value (a host's provider, judge, tool, a table row from another package) is checked with an open guard per `patterns.md` § Foreign contracts, never an exact record guard. An owned record (a snapshot, a job, a definition) is checked exactly. Paths are `src/core/` of the named package unless they name `tests`, `guides`, or `studies`. "[ran]" marks the door readings on contract 0.0.21 under Node 22.23.4 on 2026-11-04; every other line is read. Each ruling can be reopened by the user.

'allow'`. 4. **Tool.** (a) The door at `Tool.ts:64-81` is the settled door: an `explain` fault refuses; an `audit` `extra` refuses, and the one escape is a shape declared open (`objectShape(..., { additionalProperties: true })`, or a schema whose `additionalProperties` is absent or `true`); an audit of `FAULT_LIMIT` entries refuses; a `variant` or `oneOf` fault refuses (no repair through a union, which parses by declaration order); then `parse` hands the arguments on. `contract` publishes the lossless repair rule of `semantics.md` section 5, and `tool`, `workflow`, and `reason` use it: a door refuses a repair that fails it. The 2026-11-04 cross-vendor reading found meaning-changing coercions: `1` to `true`, `'9007199254740993'` rounds, `'1e-400'` becomes 0, and `'0x10'` becomes 16. `parse` itself keeps its coercions for form input. The `reason` door runs inside `execute` under `strict: false`. A refusal is `ToolError('ARGUMENTS')` whose message lists every fault, bounded by `FAULT_LIMIT`, and whose `context.faults` carries them. (b) A hand-written `parameters` record is advertised verbatim, and the lenient `schemaToShape(parameters)` is compiled on the first `execute`, memoized on the instance; with the contract rows following, the compiled shape refuses a subset of what the schema itself refuses and never more, because every keyword the walk cannot express widens its node. A conversion or compile throw (a schema that is not a readable record graph; a JSON-parsed schema never throws) is `ToolError('SCHEMA')` thrown from `execute` with the cause, which `ToolManager` reports as a failure result naming the tool. A `contract` shape compiles at construction as on 2026-11-04: an owned declaration fails early, a foreign schema fails at use. `ToolOptions.strict?: boolean`, default `true`; `strict: false` is the raw passthrough: nothing compiled, arguments forwarded verbatim, the advertised schema untouched. The name is `strict` because Agent, `AgentProvider`, the ledger, and ndjson name this switch so, and `validate` is a verb that names no assertion (`names.md` § General vocabulary). (c) A tool with neither option advertises and enforces `{ type: 'object', properties: {}, additionalProperties: false }`: a tool that declared nothing takes nothing. (d) `name` is a non-empty trimmed string, else `ToolError('SCHEMA')`. Safe because `open`, `create`, and `destroy` then stop instead of overwriting, and `store.delete` does not read.
9. **mcp:** `tools()` throws `MCPError` on a non-record result, a non-array `tools`, or a descriptor without a string `name` and a record `inputSchema`; it follows `nextCursor` and throws `MCPError` past `MCP_LIST_PAGES` (64) or on a repeated cursor, so a cut listing never reads as complete, and `nextCursor` of `null` or `''` ends a listing, because a false refusal loses the whole list for a server that sends either.
